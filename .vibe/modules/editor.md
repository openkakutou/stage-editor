# Module: editor
**Role:** The editing screens and the save flow (backlog items 003, 004, 006, 007, 008, 009). `characteristics-editor.ts` edits a loaded stage's name, author, camera bounds, and stage boundaries. `elements-editor.ts` lists, adds, edits, and removes the stage's BG elements, one collapsed row each, and (item 007) lets the user multi-select rows by checkbox — plain click/Space toggles one, Shift-click/Shift-Space selects the whole range since the last individually-selected row — and apply a shared position offset, sprite reassignment, or **delete** (item 009: a `variant="danger"` "Delete N selected" button, no confirm step of its own — relies on Undo as the recovery path, with an inline status message naming how many were deleted) to the selection in one action; selection is tracked by element object reference, never array index, so removing a row never needs reindexing. `renderElementsEditor` returns a handle (`triggerAddElement`/`triggerDeleteSelection`, `undefined` when no stage is loaded) the keyboard shortcut dispatcher (`shortcuts` module, wired from `app`) calls into, running the exact same code path as a real click. `model-editor.ts` edits a stage's Ikemen GO 3D model settings — assign/remove a 3D model and `.hdr` lighting file, the model's placement/scale/lighting strength, the 3D camera, `[Scaling]`, and each player's starting depth — and mounts the live 3D preview (`model-preview.ts`, `model-camera.ts`). All three screens mutate the given `StageData` object in place — no patch object, no re-parse round trip. `characteristics-editor.ts` and `elements-editor.ts` additionally build an undo/redo `Command` for every commit (backlog item 008) via `field-command.ts`'s shared `fieldCommand` helper (or a plain `Command` literal for a structural change: add, remove, a type switch, a batch apply/delete) and hand it to their own `onChange`, which the caller (`app`) pushes onto the shared `CommandStack`; `model-editor.ts` is not wired to undo/redo (out of this item's stated scope). `undo-redo-controls.ts` renders the toolbar's Undo/Redo buttons as a thin view over that stack's `canUndo`/`canRedo`/`undo`/`redo`. `save-export.ts` reads the document store fresh at click time, serializes it back to `.def` bytes via the WASM bridge, triggers a browser download of the result and marks the document saved (clearing unsaved-changes tracking), or shows the bridge's own error text on a reported failure; `renderSaveExport` returns a handle (`triggerSaveExport`, `button`, `unsubscribeLocale`) the keyboard shortcut dispatcher calls into and binds a live shortcut-hint label onto. Localization (item 010): every screen's static text goes through `i18n.ts`'s `t()`. `characteristics-editor.ts` and `model-editor.ts`'s static panels hold no locale-sensitive state — `app` just re-invokes their render calls on a language switch. `elements-editor.ts` keeps its selection/expanded-rows state across that same re-render, since `app` reuses the exact `rerenderElements` closure it already calls for other full-list rebuilds. `save-export.ts` keeps its own status (idle/saving/saved/error) as a small tagged descriptor and `model-preview.ts` keeps its failure-banner reason the same way, each subscribing to `onLocaleChange` internally to reformat already-shown text in place without re-running the save/load that produced it — `save-export.ts`'s own subscription must be explicitly stopped via the returned `unsubscribeLocale` before a fresh `renderSaveExport` call, since (unlike `lifebar-editor`'s equivalent) this component is re-mounted on every new document load, not once per app session.
