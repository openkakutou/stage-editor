# Module: shortcuts
**Role:** This app's keyboard shortcuts (backlog item 009), wired through `@openkakutou/web-ui-kit`'s shared, headless `ShortcutManager` and its `<wuik-shortcuts-panel>` UI instead of hardcoded key handlers — ported from `lifebar-editor`'s own identical module, extended with the two actions that repo didn't have (Add BG Element, Delete Selection). `app-shortcuts.ts` declares the five registered actions and `handleAppShortcutKeydown`, which resolves a live `keydown` event against the manager's current (default or user-rebound) bindings and calls the matching handler; Undo/Redo/Delete Selection defer to native in-field editing via `isEditableTarget` (a genuine text-entry `<input>`/`<textarea>`/contenteditable — deliberately *not* a checkbox, since checking a row then pressing Delete is the primary keyboard flow for Delete Selection), while Save/Export and Add BG Element always fire regardless of focus. The dispatcher also no-ops on an already-`preventDefault()`-ed event, since `<wuik-shortcuts-panel>`'s own rebind-capture prevents default on every key it captures without stopping propagation — without this guard the very keystroke that rebinds an action would immediately re-fire whatever now owns that key. `app-shortcut-manager.ts` holds the single module-level `ShortcutManager` singleton, persisting overrides under this app's own `localStorage` key. `shortcut-label.ts`'s `bindShortcutLabel` keeps a button's `title`/`aria-keyshortcuts` live-synced to an action's current binding. `shortcuts-panel-section.ts` wraps `<wuik-shortcuts-panel>` in a collapsible section, starting expanded (the only discovery path for this feature).
**Files:** `src/shortcuts/app-shortcuts.ts`, `src/shortcuts/app-shortcut-manager.ts`, `src/shortcuts/shortcut-label.ts`, `src/shortcuts/shortcuts-panel-section.ts`
