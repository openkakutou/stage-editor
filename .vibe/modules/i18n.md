# Module: i18n
**Role:** This app's localization setup (backlog item 010): wires the shared `@openkakutou/web-ui-kit` i18next integration layer (`initI18n`, `t`, `onLocaleChange`, `<wuik-locale-switcher>`, roadmap decision `023`) under this app's own namespace (`stage-editor`) and its own `localStorage` key (`stage-editor-locale`, distinct from `web-ui-kit`'s shared default so a locale choice never leaks into another OpenKakutou app on the same GitHub Pages origin). `initAppI18n()` is only ever called once, from `main.ts`'s async `mount()` bootstrap, awaited before the first `renderApp` — `renderApp` itself, and every other render function, stays synchronous. `t(key, defaultValue, vars?)` returns the interpolated `defaultValue` verbatim (never a raw key, never blank) whenever `initAppI18n` hasn't resolved yet in the page, so every existing test keeps asserting plain English text unchanged without bootstrapping i18n itself — every call site's `defaultValue` is kept identical, character for character, to its `en.json` entry. `en.json`/`fr.json` hold every user-facing string this app owns; the app's own brand name ("Stage Editor") and raw stage data (an element's name, its `type` enum value, numeric coordinates) are never translated. See `.vibe/decisions/008-i18n-integration-approach.md` for the full design, adapted from `lifebar-editor`'s own identical item.
**Files:** `src/i18n/i18n.ts`, `src/i18n/en.json`, `src/i18n/fr.json`
**Exports:** `initAppI18n(): Promise<I18nInstance>`, `t(key: string, defaultValue: string, vars?: Record<string, string>): string`, `onLocaleChange(callback: () => void): () => void`, `getI18n(): I18nInstance | undefined`, `NAMESPACE: string`, `STORAGE_KEY: string`
**Depends on:** `@openkakutou/web-ui-kit` (`initI18n`, `getI18n`, `onLocaleChange`, `I18nInstance`, `LocaleCatalogs`, `WuikLocaleSwitcherElement`, typed via the ambient module declaration in `src/types/web-ui-kit.d.ts` — the installed package still ships no `.d.ts` of its own)
